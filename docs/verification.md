## 真实消息验收方法

先确认菜单的系统通知状态为「监听中」，再从飞书产生数条符合已保存策略和过滤规则的新通知，逐条记录系统是否出现、浮层是否出现、是否在所有屏幕出现、出现延迟及有无重复。另用其他应用产生新通知，分别验证默认关闭时不进入浮层或最近提醒、显式启用后按所选停留时间展示。分母应为本轮系统实际收到的通知数，不能把未发送成功的消息计算成工具漏收。批量突发、立即清除和通知更新分别测试。

在设置窗口点击「发送系统通知测试」，分别记录「横幅 … 毫秒」和「数据库 … 毫秒」，主动系统测试只测量接收通道，不进入浮层或最近提醒；浮层单独用「显示测试通知」核对。横幅测试需辅助功能已授权且本应用系统横幅开启，数据库测试需完全磁盘访问。耗时包含 macOS 投递和本工具调度，不包含排队后才展示的等待；不代表飞书消息在其服务端产生后的总延迟。连续测试时记录每次耗时和样本数，不只挑最快一次。普通通知的「Go」/「Go & Close」只需激活来源应用，不应再打开通知中心或定位消息。

Codex 验证需使用实际会触发审批的测试会话，并在原 CLI 中完成批准或拒绝；另行触发一条真实提问，确认回答后相应提醒清除。手动发送的样例 JSON 仅验证桥接与展示，不计为真实 Codex 事件验证。

完成通知先保持默认关闭，确认一次真实回复结束不显示。显式开启后配置两个目录，分别在命中目录、其子目录及相似前缀目录（例如 `learning-other`）完成一轮回复；前两者应显示，后者不显示。中断与单独退出不产生完成通知，回复完成后立即退出不应清除刚出现的完成卡片。完成策略设为「不通知」后，审批与提问仍按原策略处理。
